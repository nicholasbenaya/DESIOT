Modul 1: Fondasi, Filosofi & Evolusi
Esensi IoT vs Embedded Systems Filosofi

Bukan Sekadar Benda + Internet: IoT adalah sistem siklus tertutup (closed-loop) berskala masif: mengumpulkan data fisik, mengirimkan, menganalisis, dan mengambil aksi nyata secara otomatis tanpa campur tangan manusia konstan.

Perbedaan Mendasar: Embedded System merancang 1 node tunggal; Desain & Aplikasi IoT merancang orkestrasi banyak node terdistribusi agar tetap hidup bertahun-tahun di lingkungan nyata.

Evolusi: RFID ke M2M hingga AIoT Sejarah
  • RFID (1999, Kevin Ashton, P&G): Pelacakan pasokan barang otomatis via gelombang radio pasif. Gagasan awal koneksi benda fisik.
  • M2M (Era 2000-an): Komunikasi point-to-point antar 2 mesin tertutup (silo) via kabel industri/SMS, tanpa integrasi IP terbuka.
  • IoT (2010-an ke atas): Standar internet terbuka (IP), data diintegrasikan ke platform cloud, analitik terpusat berskala besar.
  • AIoT (Modern): Kecerdasan buatan digeser mendekati fisik (edge computing) agar node mampu mengambil keputusan mandiri.
4 Sumbu Kompromi Mutlak (Trade-off) Fisika Radio
  • 1. Jangkauan (Range): Jarak tempuh transmisi (meter hingga km).
  • 2. Laju Data (Throughput): Kapasitas bit per detik.
  • 3. Konsumsi Energi: Arus listrik & ketahanan baterai.
  • 4. Biaya (Cost): Harga komponen hardware + operasional jaringan.

Hukum Alam: Tidak ada teknologi yang merajai keempat sumbu! Jarak puluhan km + baterai bertahun-tahun = laju data wajib dikorbankan (hanya belasan byte/menit, bukan video).

Modul 1 & 2: Protokol & Metodologi
4 Model Komunikasi Data IoT Protokol
  • 1. Request-Response (REST API):
    • Prinsip: Klien bertanya, server menjawab (stateless via HTTP/HTTPS).
    • Sifat: Server pasif. Overhead header paket besar (ratusan byte). Kurang ramah untuk sensor baterai kecil yang tidur panjang.
  • 2. Publish-Subscribe (MQTT):
    • Prinsip: Publisher terbit data ke Broker pada topik tertentu; Subscriber menerima instan.
    • Sifat: Overhead sangat kikir (header biner hanya 2 byte). Decoupled ruang dan waktu. Standar emas telemetri IoT.
  • 3. Push-Pull (Message Queue):
    • Prinsip: Produsen dorong pesan ke buffer antrean (Kafka/RabbitMQ); Konsumen tarik pesan bergantian.
    • Sifat: Menjamin tidak ada data hilang saat traffic melonjak tinggi (load balancing antrean pekerja).
  • 4. Exclusive Pair (WebSocket):
    • Prinsip: Sambungan dua arah (full duplex) tetap terbuka terus-menerus setelah handshake awal.
    • Sifat: Latensi ultra-rendah, ideal untuk live monitoring dan streaming data frekuensi tinggi.
Mengapa Butuh Metodologi Desain? Filosofi

Kesalahan Paling Mahal: Buru-buru membeli papan mikrokontroler sebelum memahami masalah secara sistematis. Metodologi adalah urutan pertanyaan logis yang mencegah revisi arsitektur di tengah jalan.

10 Langkah Bahga & Madisetti Metodologi

ZONA APA & MENGAPA (Langkah 1-5, Bebas Merek):

  • 1. Purpose & Requirements: Menentukan tujuan sistem & perilaku pengguna. Merumuskan kebutuhan fungsional & nonfungsional terukur.
  • 2. Process Specification: Diagram alir proses kerja sistem langkah demi langkah (termasuk kondisi anomali & state machine).
  • 3. Domain Model: Memetakan entitas dunia masalah (Physical Entity, Virtual Entity, Device, Resource, Service).
  • 4. Information Model: Mendefinisikan struktur data, atribut statis, atribut dinamis, dan tipe satuan.
  • 5. Service Specification: Menentukan menu layanan data (tipe native/network, endpoint topik/URL, jadwal periodik/event).

ZONA BAGAIMANA (Langkah 6-8, Arsitektur Mengikat):

  • 6. IoT Level Specification: Memilih tingkat arsitektur 1 s.d. 6 berdasarkan skala node, volume data, dan kendali kritis.
  • 7. Functional View: Pengelompokan blok fungsi sistem (Device, Communication, Services, Security, Management, Application).
  • 8. Operational View: MEMILIH PERANGKAT & PROTOKOL NYATA (di sinilah merek chip SoC, modul, antena, dan vendor cloud baru boleh muncul!).

ZONA PEMBUATAN (Langkah 9-10, Implementasi):

  • 9. Device Integration: Perakitan fisik modul, skema sirkuit daya, integrasi sensor & aktuator pada PCB.
  • 10. Application Development: Pemrograman logika firmware, backend cloud, basis data, dan aplikasi UI pengguna.

Jebakan Level 3 & Analisis Kasus Tangki Air Penting

Jawaban Naif (Level 3): Sensor atap kirim level air ke cloud, logika pompa dieksekusi di script cloud, cloud kirim perintah nyala/mati ke pompa bawah.

Bahaya Fatal: Jika koneksi internet kampus putus atau server down, perintah mati pompa tidak pernah sampai! Akibatnya air meluap membanjiri gedung atau pompa terbakar kering (dry-run).

Solusi Benar (Level 6 + Local Control Loop): Logika keselamatan dan interlock dry-run dijalankan langsung di kontroler lokal tanpa bergantung internet. Cloud hanya untuk analitik riwayat dan monitoring jarak jauh.

Domain Model: Fisik vs Alat vs Virtual Konsep
  • Physical Entity: Benda nyata yang kita pedulikan (Air di Tangki Atap Gedung GKB ITS). Bukan Device!
  • Device: Alat perantara untuk mengukurnya (Sensor ultrasonik).
  • Virtual Entity: Representasi digital di database (TangkiAtap#GKB-01).
  • Resource: Kode firmware di MCU pembaca tegangan sensor.
  • Service: Endpoint pemancar data (misal: pub its/gkb/tank/level).
4 Kendala Nonfungsional Terukur Spesifikasi

Setiap syarat wajib berpasangan dengan angka dan cara uji:

  • Energi: Node atap tahan ≥ 12 bulan; hidup ≥ 7 hari tanpa matahari. Uji: ukur arus rata-rata satu siklus.
  • Latensi: Interlock pompa dry-run putus dalam ≤ 2 detik. Uji: simulasi sumur kering, catat waktu respon relay.
  • Ketersediaan (Availability): Mode otomatis jalan mandiri ≥ 72 jam saat internet mati total. Uji: cabut kabel WAN.
  • Biaya: Biaya per node ≤ Rp 750.000; gateway ≤ Rp 2.000.000.
Tiga Anggaran Wajib Rekayasa Perancangan
  • 1. Anggaran Energi: Menghitung konsumsi muatan (Q = ∑ I × t) untuk memastikan kapasitas baterai mencukupi target umur pakai.
  • 2. Anggaran Latensi: Memetakan waktu tunda transmisi radio, pemrosesan edge, dan eksekusi aktuator agar sistem fisik aman.
  • 3. Anggaran Biaya: Menghitung total biaya kepemilikan (TCO): komponen hardware + lisensi gateway + langganan paket data/server.

Modul 3: Node IoT, Energi & Sensor
Profil Arus Siklus Kerja (Duty Cycle) Manajemen Daya

Sensor baterai tidak boleh hidup terus. Node menerapkan siklus:

  • Deep Sleep: 10-20 μA, CPU & radio mati, RTC timer aktif.
  • Wake-up: Kristal osilator stabil, CPU menyala.
  • Sensing: Sensor aktif mengukur parameter (5-15 mA).
  • Processing: CPU mengemas biner payload (15-30 mA).
  • RF Transmission: Radio memancar data (100-150 mA, sekejap).
Rumus Lengkap Anggaran Energi Formula Kunci
Q_siklus = (I_tidur x t_tidur) + (I_aktif x t_aktif)
I_avg = Q_siklus / t_total_siklus
Umur (jam) = Kapasitas_baterai (mAh) / I_avg (mA)
Umur (bulan) = Umur (jam) / (24 x 30)

Duty Cycle: Tuas terbesar penghemat daya. Tidur 99% waktu memangkas arus rata-rata dari ratusan mA menjadi fraksi mA.

Jebakan Papan DevKit vs Papan Produksi Hardware Trap
  • Datasheet SoC: ESP32 deep sleep tercatat ~10-15 μA.
  • Fakta Papan DevKit: Diukur menyedot 3 hingga 10 mA!
  • Penyebab Kebocoran:
    1. Regulator LDO murah (AMS1117 quiescent current 5-10 mA).
    2. Chip USB-to-UART (CP2102/CH340 terus menyala memakan daya).
    3. LED indikator daya merah (menyedot 2-5 mA non-stop).
  • Solusi Industri: Gunakan regulator ultra-low quiescent (<1 μA), lepas chip USB, matikan LED indikator.
Baterai Bukan Tangki Bensin Fisika Baterai
  • Resistansi Internal (R_int): Begitu radio transmisi menarik arus kejut (150 mA), tegangan drop seketika (ΔV = I × R_int). Jika tegangan jatuh di bawah ambang operasi MCU, terjadi brownout reset berulang.
  • Suhu Ekstrem: Panas di atap meningkatkan laju self-discharge (kebocoran daya sendiri) dan mempercepat penuaan baterai.
Karakteristik Sensor & Kalibrasi Sensorika
  • Akurasi vs Presisi: Akurasi = kedekatan ke nilai acuan; Presisi = konsistensi pengulangan bacaan.
  • Drift: Pergeseran nilai bacaan akibat penuaan / suhu.
  • Kalibrasi: 1-Titik (zero offset), 2-Titik (gain/kemiringan span), Multi-Titik (mengompensasi ketidaklinearan kurva).
  • Metadata Wajib: Angka tanpa konteks berbahaya. Tiap paket data wajib bawa: ID Perangkat, Timestamp UTC, Satuan, Status Baterai.
Mencuplik Murah, Mengirim Sangat Mahal Prinsip Emas

Energi 1x kirim radio = energi 208x pembacaan sensor! 4 strategi reduksi data tanpa kehilangan informasi:

  • Deadband Reporting: Kirim data hanya jika delta nilai > ambang.
  • Local Edge Aggregation: Cuplik tiap detik di RAM, kirim rata-rata per 10 menit.
  • Adaptive Sampling: Laju cuplik otomatis naik saat kondisi dinamis.
  • Teorema Nyquist: Laju cuplik f_s ≥ 2 × f_max. Di IoT, anggaran energi mengikat jauh lebih ketat dibanding Nyquist.
Modul 4: Konektivitas Jarak Pendek
Hukum Fisika Radio: Shannon & Link Budget Fisika Gelombang
C = B x log2(1 + SNR)  (Kapasitas Shannon)
P_rx = P_tx + G_tx + G_rx - PathLoss - Margin ≥ Sensitivitas
FSPL (dB) = 20log10(d) + 20log10(f) + 20log10(4π/c)
  • 2.4 GHz vs Sub-GHz (920 MHz): 2.4 GHz bandwidth besar namun redaman beton sangat tinggi (>15 dB/dinding). Sub-GHz panjang gelombang besar, difraksi & penetrasi halangan jauh lebih unggul.
  • RSSI: Hanya indikator daya kasar, berfluktuasi drastis akibat interferensi pantulan gelombang (multipath fading).
Wi-Fi (IEEE 802.11 b/g/n/ax) Throughput Tinggi
  • Kelebihan: Laju data masif (>10 Mbps), langsung terhubung ke internet IP tanpa gateway penerjemah, AP sudah tersebar luas.
  • Kelemahan: Sangat boros daya (~100 μAh per laporan), proses asosiasi & jabat tangan (DHCP/WPA2) lama (beberapa detik). Mustahil tahan bertahun-tahun dengan baterai koin kecil.
Bluetooth Low Energy (BLE 5.0) Ultra Low Power
  • Konsep: Dirancang untuk menyemburkan paket data kecil secara kilat lalu segera tidur (bukan streaming audio).
  • Advertising (Kanal 37, 38, 39): Menyiarkan paket data pada kanal khusus di sela frekuensi Wi-Fi tanpa proses pairing. Smartphone / gateway membaca langsung dari beacon frame.
  • GATT (Generic Attribute Profile): Struktur hierarki data: Profile → Service → Characteristic (lokasi nilai data).
  • Fitur Lanjutan: BLE Coded PHY (jangkauan ratusan meter) & BLE Mesh (komunikasi jala antar perangkat BLE).
Zigbee (IEEE 802.15.4) & Jaringan Mesh Jaringan Jala

Perangkat saling estafet pesan seperti rantai manusia (30 m/hop):

Kapan Wi-Fi, BLE, atau Zigbee? Aturan Praktis
  • Wi-Fi: Listrik tersedia konstan, butuh throughput tinggi (kamera, smart speaker, OTA firmware update besar).
  • BLE: Jarak pendek, antarmuka langsung ke smartphone, sensor personal/wearable bertenaga baterai koin.
  • Zigbee: Smart home dalam gedung banyak ruangan dengan colokan listrik tersebar untuk router (sakelar lampu, sensor pintu).

LoRa vs LoRaWAN & 3 Kelas Perangkat Protokol Jaringan

LoRa = Lapisan fisik radio. LoRaWAN = Protokol jaringan MAC arsitektur Star-of-Stars via Network Server terpusat.

  • Kelas A (All): Paling hemat baterai. Hanya buka 2 jendela dengar (RX1/RX2) sesaat setelah kirim uplink, lalu tidur. Wajib di semua node.
  • Kelas B (Beacon): Jendela dengar terjadwal via sinyal beacon dari gateway. Cocok untuk meteran air pintar.
  • Kelas C (Continuous): Mendengarkan terus-menerus. Sangat boros daya, wajib colok listrik PLN (lampu PJU pintar).
Regulasi Frekuensi & Duty Cycle di Indonesia Hukum Kominfo
  • Frekuensi Legal Indonesia: 920 - 923 MHz (Standar AS923-2). Modul 868 MHz (Eropa) & 915 MHz (USA) adalah ILEGAL.
  • Batasan Duty Cycle 1%: Hukum membatasi modul memancar maks 1% waktu. Jika memancar 1 dtk, WAJIB diam 99 dtk! Pada SF12 (airtime 2.3 dtk), jeda wajib adalah 228 detik (~4 menit), sehingga ilegal mengirim tiap 30 detik.
Jaringan Seluler IoT (NB-IoT & LTE-M) vs Sigfox Operator Seluler
  • NB-IoT: Pita berlisensi BTS operator, jangkauan nasional, penetrasi basement hebat (+20 dB). Fitur hemat daya: PSM (Power Saving Mode) & eDRX. Bayar pulsa/kartu SIM bulanan per node.
  • LTE-M: Bandwidth 1.4 MHz, laju data 1 Mbps, dukung mobilitas cepat (handover BTS) & panggilan suara (pelacak kendaraan).
  • Sigfox: Ultra-Narrowband (UNB), 140 pesan/hari @ 12 byte, milik operator tunggal tertutup.

Alur 6 Pertanyaan Penentu Pemilihan Pohon Keputusan

1. Jarak > 100m? → Wi-Fi/BLE/Zigbee gugur.
2. Ada colokan listrik perantara? → Tidak ada = Zigbee Mesh gugur.
3. Ukuran data > 1 kB / sering? → LPWAN gugur (duty cycle).
4. Butuh dihubungi instan tiap saat? → LoRa Kelas A gugur.
5. Banyak node & masa hidup lama? → Bangun gateway LoRa sendiri menang.
6. Siapa perawat sistem? → Orang awam = sederhanakan sistem.
